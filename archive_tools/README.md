# Private ChatGPT archive importer

This standard-library Python tool imports explicitly supplied ChatGPT JSON exports or ZIP exports into a **private external directory**. It does not search the computer, contact ChatGPT, run exported code, use a provider, extract ZIP members to their supplied paths, or publish anything to the research atlas.

No real conversation export was used to develop the importer. The checked-in fixture is entirely synthetic. Export formats change: a successful synthetic test is not proof that every historical or future export schema is understood. Review each run's coverage report.

## Run locally

Python 3.10 or newer; no package installation is needed. From the repository root:

```powershell
python -B -m archive_tools.import_chatgpt 'D:\PrivateExports\conversations.json' `
  --output 'D:\PrivateResearch\I-AM-Archive' `
  --keyword QFP --keyword 'regular center' `
  --as-of '2026-11-11T00:00:00Z'
```

Pass several explicit JSON/ZIP paths to combine exports. A ZIP may contain multiple files named `conversations.json`; each occurrence, including duplicate member names, is preserved with its entry index. Plain JSON supports a conversation list, one conversation object, an ID-to-conversation object, and `conversations`, `items`, or `data` wrappers. Graph `mapping` objects and flat `messages` lists/maps are recognized. Unknown formats or fields are retained in original sources and reported where normalization is incomplete.

Without `--output`, the parent is `%LOCALAPPDATA%\I-AM-Research\private-archive` on Windows or `~/.local/share/I-AM-Research/private-archive` when `LOCALAPPDATA` is absent. Every run creates a unique directory and never overwrites an earlier run. **Any output inside this repository, including ignored paths, is refused. Paths under a directory named `WEB` are also refused.** Resolved paths are checked to account for ordinary symlinks/junctions. This is not a defense against an attacker concurrently replacing filesystem links.

The output contains sensitive original data, potentially including secrets that were present in the export. It is not encrypted or redacted: doing that would compromise source preservation. Windows access control is inherited from the chosen parent; the tool does not configure ACLs. Choose a private, unsynced location with appropriate access permissions. Do not add the output to Git, a public web root, cloud storage, telemetry, or a search service. No public atlas artifact is generated by this tool.

Exit codes: `0` = normalization completed without structural/source issues; `2` = completed with reported gaps; `1` = rejected request or failed/incomplete run. Missing attachments and unknown metadata are coverage limitations even when the exit code is `0`. Inspect `manifest.json` and `coverage.json` before using results.

## What is retained

- Exact original source bytes, filenames, source paths, SHA-256, sizes, and ZIP container/member provenance. ZIP archives remain intact, including attachments; attachment contents are not opened for interpretation.
- Every recognized conversation and every message in every graph branch. Source IDs, mapping keys, parent/child arrays, current node, roles, authors, timestamps, content, regeneration-related metadata, attachment references, model metadata, and all unknown fields remain in `raw` records.
- A current-branch index computed from the exported current node through its actual parent links. It does not choose the most recent-looking message or discard alternative branches. Parent cycles on any branch, dangling links and parent/child disagreements in either declared direction are reported as coverage gaps. A valid current branch can coexist with malformed alternatives. A branch may reflect an edit or regeneration; its cause is not invented.
- Repeated and conflicting payload versions. Nothing is merged, overwritten, or declared authoritative. A repeated identity with different payloads means “same ID, different payload”; this can be a legitimate later export, not necessarily an error or contradiction.
- Raw timestamp values and, when possible, an explicit UTC representation. Numeric epochs are interpreted as seconds. Timezone-naive strings remain timezone-unknown. A conversation date is never substituted for an undated message. An epoch's UTC reference does not reveal the author's local timezone.
- Missing model, role, author, language, and timestamp metadata remain unknown. A declared default model is stored separately and does not establish which model generated a message. Content is never used to infer authorship or language.

The exact source bytes are the fidelity authority. Normalized JSON preserves parsed data, not lexical spelling, formatting, numeric precision beyond Python's JSON number handling, or repeated object keys. Duplicate object keys are explicitly reported; their complete original representation remains in the source copy. The tool does not validate scientific claims, establish historical priority, or identify which participant originated an idea.

If a document contains several recognized conversation wrappers, or a conversation contains both graph and flat message containers, the first recognized representation is normalized and the alternatives remain in the original source. The run is explicitly marked with reported gaps rather than implying every container was indexed. Exact-byte source hashes and parsed-payload version hashes serve different purposes; decimal spellings or precision differences can disappear from parsed-payload comparisons while remaining in the original copies.

## Run files

| File | Purpose |
| --- | --- |
| `manifest.json` | Version, runtime, input provenance, hashes, limits, timestamps and completion state |
| `sources/source-NNNN/original.*` | Exact source bytes; these remain private |
| `conversations.jsonl` | Conversation occurrences, raw records, complete graph nodes and current ancestry |
| `messages.jsonl` | Message occurrences, exact parsed content, raw metadata, dates and source links |
| `attachments.jsonl` | Attachment references, archive member matches or missing/unknown states |
| `unsupported.jsonl` | Recognizable document entries that could not be normalized as conversations |
| `duplicates.json` | Same-payload occurrence groups; no data removed |
| `conflicting-versions.json` | Same-identity/different-payload groups; all versions retained |
| `date-views.json` | Two- and three-calendar-year message/conversation indexes and unknown-date list |
| `keyword-candidates.jsonl` | Literal, case-insensitive title/content matches for discovery only |
| `coverage.json` | Counts, date range/months, unknown fields, duplicate/conflict counts, graph issues, attachment states and format gaps |

Counts are source **occurrences**, so overlapping exports increase counts. IDs generated by this importer identify source occurrences and payload versions; they do not replace source IDs or prove participant identity. Keyword matching is a candidate index, not an authorship inference, scientific classification, or topic filter. The full supplied corpus remains available regardless of keywords and dates. Two-/three-year views use inclusive calendar-year UTC boundaries relative to `--as-of`, or the current UTC time if omitted; leap-day cutoffs use February 28. Future and undated messages remain in the full corpus.

Unknown-metadata counters distinguish a missing `author_field` from a missing `declared_author_name`; an author object containing only a role does not establish a named participant. A supplied name remains metadata, not verified identity. Missing `current_node` is counted without choosing an alternative branch.

Exact archive member-name matches establish metadata presence only. Filename/file-ID candidates remain unverified correspondences. Plain JSON imports do not automatically inspect sibling folders for attachments; they report attachment files as not supplied. External URLs are never fetched. Missing original exports, deleted messages, and account-history completeness cannot be established from supplied files alone.

## Resource and ZIP boundaries

Defaults: 100 inputs, 512 MiB per source, 2 GiB total source bytes, 128 MiB per JSON document, 20,000 ZIP entries, 2 GiB declared uncompressed ZIP size, compression ratio at most 200, JSON nesting at most 100, 50,000 conversation occurrences, 500,000 nodes, and 250,000 messages. Each numeric limit is available as a CLI flag, for example `--max-json-bytes` or `--max-messages`; `--help` lists all flags.

Limits fail the run visibly rather than silently truncating it. An incomplete run retains a `FAILED_INCOMPLETE` manifest and any already preserved inputs/partial records. Do not mistake those partial files for a complete corpus. Unsupported/malformed sources and unsafe archives are reported with their source bytes retained. ZIP traversal paths, absolute/drive paths, symlinks and encrypted entries are rejected. Only `conversations.json` members are decompressed, with a byte bound and the standard library's CRC verification. The ZIP central directory is parsed by Python before the entry-count check, and JSON is parsed in memory within the byte/depth bounds; this is a bounded desktop importer, not a streaming hostile-input isolation service.

## Synthetic validation

```powershell
python -B -m unittest discover -s archive_tools/tests -v
```

Tests cover lossless source preservation, alternate branches and changed parents, cycles, list/object/flat formats, duplicate/conflicting versions, date boundaries, unknown metadata, attachment inventory/missing files, duplicate ZIP names, path traversal/symlinks, limits, malformed/unsupported records, duplicate JSON keys, output boundaries, and non-overwriting runs. All test imports use temporary directories outside the repository. No real export, database, API key or network service is used.
